# Plan: 모임 참가 신청 (마일스톤 2)

**결정 근거**: 사용자와의 설계 대화 (소모임 앱의 '정모 참석' 모델 검토)
**Complexity**: Medium (10~13h)

## 무엇을 만드나

모임을 **미리** 만들어 두고, 동아리 회원이 **참가/불참**을 누르고, **당일 시각이 되면**
참가한 사람들이 그대로 그날의 명단이 된다.

```
화요일 오후    회원들이 [참가] 를 누른다        → 모임장은 코트를 몇 개 빌릴지 안다
화요일 20:00   화면이 코트 현황으로 바뀐다      → 참가한 사람이 경기 짜기 목록
```

## 핵심 판단 셋

### 1. "당일 자동 추가" 에 크론이 필요 없다

미리 심어두고 **상태만 바꾼다.** 모임을 만들 때 동아리 회원 전원을
`tournament_members` 에 넣고 `rsvp='invited'` 로 둔다. 참가를 누르면 `'going'` 이 된다.
시각이 되면 **화면이 바뀔 뿐 데이터는 이미 준비돼 있다.** '추가' 라는 동작이 없다.

pg_cron 도, 배치도, 서버 타이머도 없다. 없는 게 맞다 — 시간에 의존하는 상태 전환은
서버 시계와 사용자 시계가 어긋나는 순간 디버깅이 불가능해진다.

### 2. 미리 심는 것은 선택이 아니라 필수다

```sql
tournaments_select:  is_tournament_member(id)
```

**심어두지 않으면 동아리 회원에게 모임 자체가 안 보인다.** 참가 버튼이 있는 화면에
도달할 수가 없다. `scripts/smoke-club.ts` 가 이 동작을 이미 검사로 굳혀 두었다.

그리고 이 방식이 확정 결정과 일관된다 — *"동아리 운영진이 산하 대회를 만지는 근거는
생성 시점에 심어진 멤버 행이다"*. 회원도 같은 길로 간다. **권한 헬퍼를 한 줄도 안 건드린다.**

### 3. 전원을 심어도 기록이 거짓말하지 않는다

`rsvp` 로 가른다. 경기·기록·순위·대기열은 전부 `'going'` 만 센다.
모임 명단에 16명이 있어도 그날 참가는 12명이고, 화면과 기록은 12명을 말한다.

## 데이터

```sql
tournaments        + starts_at   timestamptz          -- 모임 시각. nullable
tournament_members + rsvp        rsvp_status          -- 'invited'|'going'|'declined'
                                                      -- default 'invited'
```

- `starts_at` 이 **nullable** 인 이유: 대회는 안 쓰고, 모임도 "지금 모여서 치는 날" 로
  즉석 개설하는 길을 막지 않는다. NULL 이면 곧바로 진행 화면
- 대회(`kind='tournament'`)는 `rsvp` 를 **안 본다.** 문서에 명시할 것
- **기존 행 backfill**: 지금 있는 모임 2개의 멤버는 스스로 들어온 사람들이므로 `'going'`.
  새로 심는 사람만 `'invited'` 로 시작한다

## 서버

### `create_session` 확장
지금은 **운영진만** 심는다. 회원까지 전부 심도록 넓힌다.

| 대상 | role | rsvp |
|---|---|---|
| 만든 사람 | owner | `going` — 만든 사람이 안 갈 리 없다 |
| 동아리 운영진 | admin | `invited` |
| 동아리 회원 | member | `invited` |

`unique_display_name` 을 그대로 태운다 (동명이인).
미가입 회원(`user_id is null`)도 심는다 — 계정이 없어 참가를 못 누를 뿐,
모임장이 대신 경기에 넣을 수 있어야 한다.

### 새 RPC `set_my_rsvp(p_tournament_id uuid, p_rsvp rsvp_status)`
- **본인 행만** 바꾼다. 남의 참가 여부를 대신 정하지 못한다
- 모임(`kind='session'`)에서만 허용. 대회에서 부르면 거절
- 이미 시작한 모임에도 허용한다 — 늦게 도착해서 누르는 게 정상 경로다

## 화면

```
시작 전                          당일 (starts_at 지남 · 또는 NULL)
─────────────────────           ─────────────────────
10월 7일 모임 · 화 20:00         코트 현황 (기존 그대로)
참가 12 · 미정 3 · 불참 1        [경기 짜기]
[참가할게요] [안 갈래요]           └ 참가 12명이 먼저
참가자 목록                        └ 그 외 회원은 접어서
```

**참가를 게이트로 쓰지 않는다.** 안 누르고 온 사람도 경기에 넣을 수 있다.
누르지 않으면 못 치게 하는 앱은 동아리에서 미움받는다.

## 리스크

| | 등급 | 완화 |
|---|---|---|
| 회원 30명 × 매주 → `tournament_members` 가 빠르게 늘어남 | 낮 | 주당 30행. 1년 1,560행. 인덱스 이미 있음 |
| 모임 생성 뒤 동아리에 들어온 사람은 그 모임에 안 보임 | 중 | **생성 시점 스냅샷**으로 두고 문서화. 재동기화는 다음 범위 |
| `rsvp` 가 대회 쪽 화면에 새어 들어감 | 중 | 대회는 이 컬럼을 안 본다. smoke 로 회귀 확인 |
| `starts_at` 시간대 혼동 | 중 | `timestamptz` 로 저장, 화면은 사용자 시간대로. 서버에서 '시작했나' 를 판단하지 않는다 |

## 하지 않는 것

- **반복 일정(매주 화 20:00 자동 생성)** — 아무도 안 오는 유령 모임을 매주 만들어낸다.
  손으로 만드는 게 실제로 귀찮은지 보고 판단한다
- **정원 마감** — 코트를 넘으면 더 기다릴 뿐이지 못 오게 할 일이 아니다
- **참가 마감 시각** — 늦게 누르는 게 정상이다
- 알림(참가 독촉) — 별개 주제
