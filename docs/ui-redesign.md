# UI 재설계 — 한 것과 남은 것

> 2026-08-27. 방향과 원칙은 [design.md](design.md) 에 있습니다. 이 문서는
> **무엇을 실제로 바꿨고 무엇이 남았는지**만 적습니다.

## 왜 시작했나

기능 검증은 500항목이 통과하는데 **"UI가 쓰는 사람을 위한 게 아니다. 플로우도
별로고 다 별로다"** 는 지적을 받았습니다. 맞는 지적이었습니다 — 지금까지 화면은
**기능이 있느냐**로 만들어졌고, 체육관에서 한 손에 폰을 들고 서서 몇 시간 쓰는
사람을 기준으로 만든 적이 없습니다.

**1순위는 귀찮지 않은 것입니다.** 조금이라도 귀찮아지면 안 씁니다.

---

## 화면을 눈으로 보는 장치

```bash
npx tsx scripts/shots.ts        # shots/ 에 로그인한 상태의 화면이 찍힌다
```

세션을 localStorage 에 직접 주입해 로그인 화면을 건너뜁니다. 데모 데이터를
만들고 찍고 지웁니다.

**이번에 고친 것 중 절반은 코드로는 안 보이고 찍어야만 보였습니다.**
검증 500항목이 전부 통과하는 동안에도 이런 것들이 있었습니다:

- 공용 대기 2경기가 네 코트에서 각자 세어져 **8경기처럼** 보였다
- 초록을 카드 배경에 칠했더니 코트 셋이 비었을 때 **화면이 초록 벽**이 됐다
- 코트 칩을 목록 아래로 내렸더니 **고정 바 뒤에 깔려 사라졌다**
  (`position:fixed` 는 문서 흐름을 밀지 않는다. 좌표를 재서 확인했다)

**테스트로는 하나도 안 잡힙니다.** 화면을 고칠 때는 반드시 찍어서 보세요.

> ⚠ **캡처 도구의 다크모드 기본값이 다릅니다.** Playwright 는 라이트, Chrome CLI 는
> 다크입니다. 이걸 모르고 비교해서 "로그인만 검정이라 같은 제품으로 안 보인다" 는
> **잘못된 진단**을 한 적이 있습니다. 비교할 때는 `colorScheme` 을 맞추세요.

## 무엇이 줄었나

| 동작 | 전 | 후 |
|---|---|---|
| **다음 경기 시작** | 탭 3회 + 모달 | **1탭** |
| **경기 짜기** | 6탭+ (참가자가 접혀 있음) | **4탭** |
| **점수 정정** | 화면 5개 · 탭 6회+ · **길이 끊김** | **화면 3개 · 사람은 다시 안 고름** |
| **코트 ↔ 대진표** | 화면 꼭대기까지 손을 뻗음 | **엄지** · 게다가 **갈 일이 줄었다** |

마지막이 제일 큽니다. 코트 화면 하나가 **"지금 뭐가 돌고 / 어디가 비었고 /
다음에 뭐가 있나"** 를 다 답해서, 대진표로 넘어갈 이유가 없어졌습니다.

## 화면별로 바꾼 것

### 코트 화면 (가장 많이 바뀜)

- 코트 카드를 **실제 코트 모양**으로 — 가운데를 가르고 양쪽에 팀, 가운데 점수
- **빈 코트를 누르면 다음 경기가 바로 시작**된다. 모달 한 단계가 사라졌다
- 초록을 **면적이 아니라 위치**로 (왼쪽 띠). 배경을 칠하면 여럿 비었을 때 안 튄다
- **공용 대기를 코트마다 세지 않는다.** 먼저 비는 코트가 집어가는 것이므로 요약줄 하나
- 대기 목록을 **숫자가 아니라 실제 대진**으로 편다
- 상단 아이콘 4개 → 제목 한 줄
- "실시간" 라벨은 **끊겼을 때만** 뜬다 (정상을 알리는 표시는 정보가 없다)

### 하단탭 (전 화면)

탭 6개가 화면 맨 위에 있던 것을 **4개(코트·대진표·기록·더보기)로 줄여 하단**에.
나머지(심판·순위·참가자·관리·설정)는 더보기 시트로. 아이콘만 두지 않고 글자를 함께.

### 경기 짜기

- **참가자를 항상 펼친다.** 아무도 참가를 안 눌렀으면 전원이 접혀 있었다
- 코트 칩 5개 → **한 줄로 접음**. 주 작업은 사람 고르기다
- **고른 사람을 하단에 고정.** 칩을 누르면 바로 뺀다
- 큰 제목과 설명문 제거. **번호와 팀 색**이 "앞 둘이 한 편" 을 대신 말한다
- 모두에게 붙는 배지("명단만")는 배지가 아니다 — 구분이 될 때만 띄운다

### 홈

- 인사말 축소 (이름이 화면에서 제일 컸다)
- **그라데이션 제거** · 카드 문법 4종 → 1종 (코트 카드와 같은 문법)
- 순서를 **사용 빈도대로** — 모임 열기 > 대회 만들기 > 참가하기
- 진행 중을 빨강 → **초록**

### 로그인

입력칸 테두리를 진하게 (어두운 화면에서 안 보였다) · 빈 공간 정리

### 점수 정정

- `window.prompt()` → **앱 모달**
- 무효 처리 후 **"다시 입력하기"** (전에는 링크가 아예 없어서 관리 허브를 스스로 찾아가야 했다)
- 조·선수·점수를 **미리 채운다.** 고치려는 것은 대개 점수 하나지 사람이 아니다

### 색 규칙 (전역)

| 색 | 전 | 후 |
|---|---|---|
| 초록 | "버튼" 이라는 뜻 | **들어갈 수 있다** |
| 빨강 | "진행 중" | **되돌릴 수 없다**(삭제·무효)만 |
| 주황 | 안 씀 | **곧 끝난다** |

**색만으로 상태를 말하지 않습니다.** 초록 띠 옆에 "비었습니다" 글자가 항상 붙습니다 —
체육관 조명·햇빛·색맹에서 색이 제일 먼저 무너집니다.

## 🔴 남은 것 — 아직 못 한 두 가지

사용자가 지적했고 **찍어서 확인한 것**입니다. 다음에 이어받을 사람은 여기부터 보세요.

### 1. 명단 관리가 편하지 않다 (`shots/m-members.png`)

**참가자 화면에 사람을 추가하는 버튼이 없다.** 11명이 나열돼 있는데 `+ 추가` 가
화면 어디에도 없다. 명단에 사람을 넣으려면 **더보기 → 관리 → 참가자**로 따로
들어가야 한다. **보는 화면과 고치는 화면이 분리돼 있다.**

그리고 **이번 작업이 이걸 더 나쁘게 만들었다.** 하단탭을 4개로 줄이면서 참가자를
더보기 시트에 넣었으므로 **탭이 하나 늘었다.** 명단 관리가 자주 하는 일이라면
탭 구성을 다시 봐야 한다.

**"조 미정" 이 주황 점선 박스로 크게 강조돼 있다.** 모임에는 조가 없는데 이게 뜨고,
주황은 이 저장소 규칙상 "곧 끝난다 · 준비해라" 다. **정상 상태에 경고색**이다 —
홈에서 고친 것과 똑같은 문제가 여기 남아 있다.

**이름만 있고 정보가 없다.** 참석 횟수 · 계정 유무 · 게스트 여부 · 오늘 몇 판 뛰었나 —
운영진이 명단에서 알고 싶은 것이 하나도 없다. 가나다순이라 "방금 온 사람" 도
"오늘 안 뛴 사람" 도 안 보인다.

> 당근 레퍼런스의 **"인증 11회"** 가 정확히 이 자리인데 비어 있다.

할 일:

- [ ] 참가자 화면에서 **바로 추가·이름 수정·빼기**
- [ ] 이름 옆에 **참석 횟수 · 오늘 경기 수 · 게스트 표시**
- [ ] **"조 미정" 주황 박스를 모임에서 빼기**
- [ ] 정렬을 가나다순 말고 **의미 있는 순서**로 (오늘 안 뛴 사람 먼저 등)
- [x] 참가자를 하단탭으로 되돌릴지 판단

> **결과 (커밋 `191fa5e`)** — 전부 했습니다. 참석 횟수 하나만 못 했습니다.
>
> ```
> 명단에 사람 추가   4탭 → 2탭
> 명단 보기          2탭 → 1탭
> ```
>
> 참가자를 **하단탭으로 되돌렸습니다** (`코트 · 대진표 · 참가자 · 기록 · 더보기`).
> 명단은 저녁 내내 바뀌고, "쟤 몇 판 뛰었지" 는 경기를 짤 때마다 보는 것입니다.
>
> **참석 횟수만 못 넣었습니다.** `tournament_members` 는 대회 하나에 종속이라
> 한 동아리의 지난 모임을 가로지르는 쿼리가 저장소에 없습니다. 새 RPC 나 집계
> 뷰가 필요해서 억지로 만들지 않았습니다 — **이게 남은 유일한 항목입니다.**
>
> 찍어서만 보인 것 넷을 함께 고쳤습니다. 그중 하나는 이 문서가 못 짚은
> 것입니다 — **'미가입' 배지가 9명 중 8명에게 붙어 배경이 됐습니다.**
> `hasAccountContrast` 의 원칙("모두에게 붙는 배지는 배지가 아니다")은 맞았고
> **임계값이 틀렸습니다**. '전원일 때만 숨김' 이 아니라 **소수일 때만 붙임**
> 입니다.

### 2. 홈이 그냥 메뉴다 (`shots/home.png`)

**흰 카드 다섯 개가 세로로 쌓인 목록이고 정보가 0이다.**

- 오늘 몇 명 온다는지 안 알려준다
- 내 다음 경기가 언제인지 안 알려준다
- 이번 달 몇 번 나왔는지 안 알려준다
- **진행 중인 모임이 없으면 화면이 텅 빈다** — 버튼 셋만 남는다

참가자(운영진 아닌 사람) 입장에선 더 심하다. **문 셋 + 목록 셋이 전부**다.

이번에 한 것은 **"위계를 정리한 것"이지 "홈을 만든 것"이 아니다.** 나쁜 배치를
덜 나쁜 배치로 바꿨을 뿐이다.

> 레퍼런스와 비교하면 명확하다 — **플랜핏 홈**은 조건 칩과 개인화된 플랜을
> **보여주고**, **당근**은 카드마다 정보가 있다. 지금 홈은 **링크만** 있다.

할 일:

- [ ] 홈을 **문 여는 곳이 아니라 오늘을 보여주는 곳**으로
- [ ] 다음 모임이 **언제고 몇 명이 참가를 눌렀나**
- [ ] **내 다음 경기** (참가자에게 제일 중요)
- [ ] 이번 달 참석 횟수 · 연속 참석 (플랜핏 캘린더 패턴)
- [x] **빈 상태**를 설계 — 진행 중인 것이 없을 때가 기본이다

> 데이터는 **전부 DB 에 이미 있다.** 홈이 안 쓰고 있을 뿐이다.

> **결과 (커밋 `a088b2c`)** — 홈의 **책임을 바꿨습니다.**
>
> 전에 홈을 "어디로 갈지 고르는 곳" 으로 만들면서 화면 하나에 책임 하나를
> 지키려고 문만 두고 정보를 하나도 안 그렸는데, 그게 이 절이 지적한 상태입니다.
> **원칙이 틀린 게 아니라 책임을 잘못 골랐습니다.** 홈에 온 사람의 질문은
> "어디로 갈까" 가 아니라 **"내가 지금 뭘 해야 하지"** 입니다. 책임을
> "오늘을 보여준다" 로 바꾸면 한 문장 그대로고 문은 그 아래 딸린 것이 됩니다.
>
> - 진행 중이면 그 하나 + **내 다음 경기 한 줄** ("3번 코트 · 앞에 2경기")
> - 없으면 가장 가까운 다음 모임 + 시각 + 몇 명이 참가를 눌렀나
> - 그것도 없으면 이번 달 몇 번 나왔는지
>
> **여전히 점수판은 아닙니다.** 코트별 현황·대기열 전체·순위는 안 그립니다 —
> 그건 코트 화면의 일이고, 두 화면이 같은 것을 다르게 보여주기 시작하면 어느
> 쪽이 맞는지 아무도 모르게 됩니다. 테스트가 이걸 지킵니다.
>
> 조심한 자리 둘 —
> **셀 근거가 없는 것을 세지 않습니다**(참석 횟수를 `joinedAt` 으로 세면 동아리
> 모임은 회원 전원이 한꺼번에 심어지므로 "동아리가 연 횟수" 가 됩니다).
> **모르는 것을 0 으로 그리지 않습니다**("0명 참가" 는 사실이 아니라 아직
> 모르는 것이라, 그 줄 자체를 안 그립니다).

### 3. 실기기 확인이 아직 0회

이번에 **하단탭과 고정 바를 여럿 붙였다.** 아래 둘은 실제 폰에서만 안다:

- [ ] **아이폰 홈 인디케이터** 영역과 겹치는가 (`safe-area-inset-bottom` 을 넣었지만 확인 못 함)
- [ ] **키보드가 올라올 때** 하단 고정 바가 어떻게 되는가 (경기 짜기 · 로그인)

## 원칙 (design.md 요약)

1. **색은 상태다. 장식이 아니다** — 그리고 색만으로 말하지 않는다
2. **제목을 지우고 정보를 키운다** — 사용자는 자기가 어디 있는지 안다
3. **자주 누르는 것은 아래에 둔다** — 화면 아래 3분의 1이 엄지가 닿는 곳

바꾸기 전과 후를 **탭 횟수로 잰다. 예쁘게 만들었는데 탭이 늘었으면 실패다.**
