# 디자인 방향

> 2026-08-26. 실제 화면을 찍어 보고 세운 것입니다 — `npx tsx scripts/shots.ts`
> 로 언제든 다시 찍을 수 있습니다.

## 이 앱이 실제로 쓰이는 상황

**체육관. 한 손에 폰. 서서. 몇 시간.**

운영진의 하루는 한 문장으로 줄어듭니다 — **"빈 코트를 찾아 다음 경기를 밀어넣는다."**
그걸 저녁 내내 수십 번 반복합니다. 그래서 이 앱의 모든 화면은 그 반복을
얼마나 짧게 만드느냐로 평가받습니다.

지금까지는 **기능이 있느냐**로 만들어 왔습니다. 검증 400여 항목이 전부
"서버가 옳게 답하나" 를 봤고, 화면은 "누르면 되나" 까지만 봤습니다.
서서 한 손으로 쓰는 사람을 기준으로 만든 적이 없습니다.

---

## 실측으로 확인한 문제

### 흐름 (코드에서 센 것)

| 흐름 | 지금 | 문제 |
|---|---|---|
| 모임 열기 | 탭 2회 | 괜찮다. 다만 동아리 선택이 **매번 초기화**된다 |
| 경기 하나 짜기 | 탭 6회 이상 | 참가자가 **접혀 있어** 한 번 더 눌러야 한다 |
| **다음 경기 시작** | 탭 3회 + 모달 | 하루에 수십 번 하는 동작에 **모달이 강제**된다 |
| 순서 바꾸기 | 드래그 1회 | 가장 잘된 흐름 |
| 게스트 링크 | 탭 4회 | 동아리가 하나여도 목록 화면을 거친다 |
| **점수 정정** | 화면 5개 · 탭 6회+ | **중간에 링크가 끊겨 있다.** 무효 처리 화면에서 재입력 화면으로 가는 길이 코드에 없다 |

### 화면 (찍어서 본 것)

- **로그인은 거의 검정, 앱은 거의 흰색.** 같은 제품으로 안 보인다
- **위계가 사용 빈도와 반대다.** 홈에서 제일 크고 화려한 것이 운영진이 가장 안 쓰는 "대회 참가하기" 다
- **한 화면에 카드 문법이 4개** (분홍 테두리 · 초록 그라데이션 · 흰 카드 · 흰 리스트)
- **색이 뜻과 반대다.** "진행 중" 이 빨강/분홍이다 — 정상 상태에 경고색
- **코트 4개가 전부 똑같이 생겼다.** 운영진이 봐야 하는 건 "어디가 비었나" 인데 빈 코트가 안 튄다
- **자주 누르는 버튼이 화면 위쪽에 있다** — 코트 화면의 "경기 짜기", 동아리의 "게스트 링크", "링크 복사". 셋 다 엄지가 안 닿는다
- **경기 짜기 화면에서 참가자 8명이 전부 접혀 있다.** 아무도 참가를 안 눌렀으면 전원이 숨는다

## 세 가지 원칙

### 1. 색은 상태다. 장식이 아니다

지금 초록은 "버튼" 이라는 뜻이고, 빨강은 "진행 중" 이라는 뜻입니다. 둘 다 틀렸습니다.

| 색 | 뜻 | 쓰는 곳 |
|---|---|---|
| **초록** | **들어갈 수 있다** | 빈 코트 · 다음 동작 |
| 중립(회색) | 지금은 건들 것 없다 | 진행 중인 경기 |
| **주황** | **곧 끝난다 · 준비해라** | 매치포인트 · 대기 2번째 |
| 빨강 | **되돌릴 수 없다** | 삭제 · 무효 처리 **뿐** |

"진행 중" 배지에서 빨강을 걷어냅니다. 경기가 도는 건 정상이지 경고가 아닙니다.

### 2. 제목을 지우고 정보를 키운다

운영진은 자기가 어디 있는지 압니다. 화면마다 큰 제목과 설명 한 줄이 붙어
**첫 화면의 3분의 1을 쓰는데**, 그 자리에 코트가 하나 더 들어가야 합니다.

- 화면 제목은 **네비게이션에 이미 있다** — 본문에서 반복하지 않는다
- 설명문("4명을 고르면 앞 2명이 한 편…")은 **처음 한 번만** 필요하다. 매번 보여줄 것이 아니다
- 대신 **숫자와 이름을 키운다.** 코트 번호 · 선수 이름 · 점수 · 대기 수

### 3. 자주 누르는 것은 아래에 둔다

한 손으로 서서 쓰는 앱이다. **화면 아래 3분의 1** 이 엄지가 닿는 곳이다.

- 그 화면에서 **가장 자주 하는 한 가지**는 하단 고정
- 채점 화면과 경기 짜기 제출은 **이미 그렇게 돼 있다** — 규칙을 앱 전체로 넓힌다
- 위쪽은 **보는 것**(상태·현황), 아래쪽은 **하는 것**(동작)

## 서명 요소 — 코트 카드를 진짜 코트처럼

지금 코트는 흰 사각형 4개이고 전부 똑같이 생겼습니다. 이 앱의 중심 사물이
아무 성격도 없습니다.

배드민턴 코트는 **가운데를 네트가 가르는 직사각형**입니다. 카드를 그 모양으로
만듭니다 — 가로로 긴 띠, 가운데 세로선, 양쪽에 팀 이름, 가운데에 점수.

```
┌─────────────────────────────────────┐
│ 1번 코트                     12 : 9 │
│ 김민수 · 이서연  │  박지훈 · 최유진  │
└─────────────────────────────────────┘

┌─────────────────────────────────────┐
│ 2번 코트                            │
│        비었습니다 · 대기 3경기      │   ← 초록. 누르면 바로 다음 경기
└─────────────────────────────────────┘
```

**빈 코트는 초록으로 튀고, 누르면 대기 첫 경기가 바로 시작됩니다.**
모달 한 단계가 사라집니다 — 하루에 수십 번 반복하는 동작이라 여기가 가장 크게 줄어듭니다.

대기 목록은 카드 안에 접힌 줄로 두고, 다른 경기를 고르고 싶을 때만 펼칩니다.
기본 동작(맨 앞 경기 시작)은 한 번, 예외 동작(골라서 시작)은 두 번입니다.

---

## 하지 않을 것

- **그라데이션** — 지금 홈의 초록 그라데이션이 유일한 장식인데, 뜻이 없다
- **다크 테마 통일** — 로그인만 검정인 건 고치되, 앱 전체를 검정으로 바꾸지는
  않는다. 체육관 조명 아래에서는 밝은 화면이 읽힌다
- **애니메이션 추가** — 지금 부족한 것은 움직임이 아니라 위계다
- **화면 새로 만들기** — 흐름을 줄이는 게 목적이지 화면을 늘리는 게 아니다

---

## 순서

1. **코트 화면** — 이 앱의 중심. 서명 요소가 여기 있고, 가장 자주 보는 화면이다
2. **홈** — 위계를 사용 빈도에 맞춘다. 카드 문법을 하나로 줄인다
3. **경기 짜기** — 참가자를 펼쳐 두고, 제목·설명을 줄인다
4. **점수 정정 흐름** — 끊긴 링크를 잇고 값을 채워 넘긴다
5. **로그인** — 앱과 같은 세계로 보이게 한다

# 컨셉 — "장부가 아니라 계기판"

> 2026-08-27 추가. 실제 배포해서 쓰게 할 것이므로, **1순위는 귀찮지 않은 것**이다.
> 조금이라도 귀찮아지는 순간 안 쓴다.

## 이 앱이 무엇이 아닌가

레퍼런스로 예약 앱(헤이딜러 날짜 선택 · 타다 RV)이 올라왔지만 **이 앱에는 예약이
없다.** 모임을 열면 바로 시작하고, 코트는 예약하는 게 아니라 **비면 즉시 집어가는
것**이다. 예약 UI 를 이식하면 없는 기능의 화면을 만들게 된다.

가까운 것은 **배달 라이더 앱 · 주방 디스플레이**다. 지금 돌아가는 상태를 보고,
비는 자리에 다음 것을 밀어넣는 도구다. 읽는 화면이 아니라 **가동 화면**이다.

## 레퍼런스에서 가져오는 것 — 원리만

| 출처 | 원리 | 여기서는 |
|---|---|---|
| 타다 | 날짜 셀 밑 **부가정보 한 줄**(−10%) — 찔러보지 않고 안다 | 코트 카드에 "대기 2 · 12분째" |
| 타다 | **고른 것을 하단에 계속 고정** | 경기 짜기에서 고른 사람이 항상 보인다 |
| 헤이딜러 | **색만 쓰지 않고 범례를 붙인다** | 초록 띠 + "비었음" 글자 |
| 헤이딜러 | **두 상태를 다르게 처리**(취소선 / 흐리게) | 끝난 경기 / 무효 경기 |
| 헤이딜러 · 타다 | **하단 고정 CTA** | 이미 적용 |
| **플랜핏** | **하단탭** | **가장 큰 변경** |
| 런드리고 | 상태 배지를 **텍스트 + 아웃라인** | 색맹·햇빛에서도 읽힌다 |
| 당근 | **신뢰 지표**("인증 11회") | 참석 횟수 — 나중 단계 |

## 귀찮음을 재는 자

바꾸기 전과 후를 **탭 횟수와 손이 닿는 거리**로 잰다. 예쁘게 만들었는데 탭이
늘었으면 실패다.

| 동작 | 지금 | 목표 |
|---|---|---|
| 코트 ↔ 대진표 | 화면 꼭대기까지 손을 뻗음 | **엄지로** |
| 다음 경기 시작 | 1탭 (개선 완료) | 유지 |
| 경기 짜기 | 6탭+ · 참가자가 접혀 있음 | **4탭 · 펼쳐진 상태** |
| 점수 정정 | 화면 5개 · 링크 끊김 | **끊긴 곳 잇기** |

## 구조 — 하단탭으로 내린다

지금 대회·모임 화면의 위쪽 구성:

```
[← 내 모임] [홈]              [관리] [설정]     ← 아이콘 4개
오늘 저녁 모임  (진행중)                        ← 제목 + 배지
[코트] [대진표] [기록] [참가자]                 ← 탭 4개
────────────────────────────────  여기까지 화면의 40%
```

운영진은 저녁 내내 **코트 ↔ 대진표**를 오간다. 매번 화면 꼭대기까지 손을 뻗는다.

바꾼다:

- **탭을 하단으로.** 엄지가 닿는 곳에 둔다
- 상단은 **제목 한 줄**만 남긴다. 뒤로가기는 남기되 홈·관리·설정은 정리한다
- 그만큼 **코트가 더 보인다**

## 색과 상태 — 범례를 붙인다

색만으로 상태를 말하지 않는다. 체육관 조명·햇빛·색맹에서 색은 제일 먼저 무너진다.

| 상태 | 색 | **함께 붙는 것** |
|---|---|---|
| 비었음 | 초록 띠 | "비었음" 글자 + ▷ 아이콘 |
| 진행 중 | 중립 | 점수 숫자 |
| 곧 차례 | 주황 | "곧 차례" 글자 |
| 끝남 | 흐리게 | "완료" |
| 무효 | **취소선** | "무효" |

끝난 것과 무효인 것은 **다른 방식**으로 처리한다(흐리게 / 취소선). 헤이딜러가
지난 날짜와 마감 슬롯을 갈라 처리한 것과 같은 이유다.
