### 적용 방법 (둘 중 하나)

**A. MCP** — `.mcp.json` 에 Supabase MCP 서버가 등록돼 있습니다.
프로젝트 폴더에서 `claude` 를 실행해야 로드됩니다 (작업 디렉터리 기준).
`/mcp` → supabase → Authenticate.

**B. DB 직결** — `.env.local` 의 `SUPABASE_DB_URL` 을 채우고:
```bash
npm run db:push
```
대시보드 Connect → **Session pooler(5432)** 문자열. Transaction pooler(6543)는 DDL 이 안 됩니다.

### 적용 후 반드시 확인할 3가지 (실패 가능성 높은 순)

1. **`auth.users` 트리거 생성 권한** — `handle_new_user` 트리거.
   막히면 대안: 앱에서 최초 로그인 시 `profiles` 를 lazy 하게 만드는 방식으로 전환.
2. **RLS 무한재귀** — `tournament_members` 정책이 자기 자신을 조회합니다.
   `SECURITY DEFINER` 헬퍼로 끊어놨지만 실제로 통과하는지 확인 필요.
   해당 테이블에 `FORCE ROW LEVEL SECURITY` 를 켜면 안 됩니다.
3. **`alter publication supabase_realtime add table matches`** — Realtime 발행 등록.

## 도메인 규칙 (헷갈리면 README 참조)

```
조 개수 N, 조커조 K → 1조~K조가 조커조로 고정
목표점수  일반 21점 / 조커 11점  (듀스 없음)
승점      일반 승리 1.0 / 조커 승리 0.5 / 패배 0
경기      조 vs 조, 각 조에서 관리자가 2명씩 선택 (복식)
```

## 설계상 절대 깨면 안 되는 것

1. **점수는 원장(`score_events`) + 투영(`matches.score_a/b`)**
   `score_events` 에 쓰기 RLS 정책이 하나도 없는 건 의도입니다 — RPC 우회를 막습니다.
2. **목표점수·승점은 `match_teams` 스냅샷**
   대회 도중 조커 구성이 바뀌어도 지난 결과가 소급 변조되지 않게 하는 장치입니다.
3. **`rules.ts` 와 `record_score` 는 같은 판정을 해야 합니다**
   낙관적 UI 용 사본입니다. 한쪽만 고치면 화면과 DB 가 어긋납니다.
